# eduediter-php
基于启发式PHP的EduEditer转换工具

## 使用

1. 保存为 `wsd_tool.php` 丢到 PHP 网站目录；浏览器直接访问该文件。
2. 功能清单

- 上传`.wsd`，上传进度条；
- PHP 后端二进制启发式解析 + 文本清洗；
- 内置**试卷状态机**自动切分：题号 / A‑D 选项 /【答案】【解析】；
- 左侧：原始文本 + 可编辑表格，所有题干、选项、答案、解析可以直接网页修改；
- 右侧 MathLive：可视化公式编辑器，双向同步 LaTeX；
- 导出 Obsidian Markdown 文件下载。

## 限制（一定要清楚）

1. 启发式解析拿不到图片、拿不到 wsd 原生公式块；只有文本碎片，乱序、垃圾字符属于正常现象。
2. 大文件同步 HTTP 会超时；生产环境要改成：文件落盘，交给 PHP‑CLI 后台任务解析，前端轮询。
3. 切题状态机对排版极乱试卷识别率下降，**必须人工编辑修正表格内容再导出**。

我以前的数学老师喜欢用一种叫做EduEditer的软件，这种格式不知道有没有人见过。它是一款类似Word和OneNote的教学编辑工具，不过它用的神秘私有二进制格式不能回转到Word，就算转PDF也要先下载这个软件，没有单独的转换工具。于是我拿Hermes+DeepSek搓了个启发式的转换工具，准确率有限，但是能基本转换含有图片的文字内容。其他格式到EE的反向暂时为实验性功能，暂时只支持转换纯文本内容。
**技术上：PHP 完全可以实现启发式二进制扫描版本，但是有明显短板；完整块逆向解析也能写，但不适合 Web-FPM 环境**。

## 1、PHP 可用底层能力

1. `fopen($fp,"rb")`二进制只读；`fseek()`随机跳转偏移；`fread()`读字节；`unpack()`解析小端整数、字节数组，具备二进制操作全部基础能力。
2. `iconv()`可以把 UTF‑16LE 二进制片段转 UTF‑8，正好匹配 wsd 内部文本编码。
3. 可以实现：魔数校验 `\x00WSTUDIO5`，滑动窗口遍历字节流，捞取 UTF‑16LE 字符串片段，和 EduConverter Python 逻辑等价。

## 2、PHP 致命短板（Web 环境 FPM 模式）

1. **内存风险**
wsd 试卷，大试卷可以几十 MB。
如果`file_get_contents`一次性全部读入 PHP 字符串，直接把整个二进制塞进内存，很容易触发`memory_limit` OOM 崩溃CSDN博...。

> 
> ✅解决：不能一次性全加载，**分块流式滑动扫描，不要把全部 bytes 读到 PHP 变量**，一块一块迭代处理。

2. **执行时间限制**
HTTP Web 请求有`max_execution_time`，大 wsd 文件字节扫描耗时久，浏览器上传解析会超时。

> 
> ✅解决：wsd 解析**不要放在同步 HTTP 接口**；丢进队列（Redis‑Queue）后台异步任务处理；前端轮询获取解析结果。

3. PHP 字符串底层是 zval，处理超大二进制字符串性能弱于 Go/Rust/Python，启发式扫描速度会比 Go 慢一些，但小试卷（几 MB）感知不明显。
4. 完整块解析版本（你未来计划）：大量`fseek`随机跳转，PHP 也能做，但大量随机 IO 在 PHP‑FPM 下体验差，更适合 CLI 命令行跑，不适合网页直接调用。

## 3、两种部署形态（PHP）

### A：启发式扫描（预览版，对标 EduConverter，现在就可以写）

> 
> 只捞文本碎片，**不做生产入库，仅预览**，输出置信度标记，提示人工校对。

- 运行环境：推荐 **PHP‑CLI**，不受 web 超时、内存限制；
- Web 端：上传 wsd 文件，把任务丢队列，CLI 消费执行解析；返回提取的原始文本，交给你现有的试卷状态机正则切分题目。

> 
> 拿不到图片、拿不到原生试题块结构，文本乱序、垃圾字符串问题和原版 EduConverter 一模一样。

### B：完整块解析（未来版本）

PHP 语法层面完全写得出来：读文件头、解析块索引表、fseek 跳各个对象块、区分文本块 / 试题块 / 图片块。
但是缺点：

1. 大量`fseek`随机 IO，PHP‑CLI 勉强跑，Web 请求不要碰；
2. 一旦 EduEditer 版本更新块结构，维护成本高；
3. 二进制调试体验远不如 Python/Rust，没有好用的二进制工具生态。

## 4、现实工程建议（结合你的岫题库）

你现在两套技术栈：PHP（老监控脚本）、Go（岫题库后端）

1. **不要把 wsd 解析放在 PHP Web 接口**。

- 方案 1：把启发式 wsd 解析逻辑用 PHP 写为 CLI 独立工具；岫题库 Go 后端通过 exec 调用这个 php cli 程序，拿到输出文本，再做后续处理。
- 方案 2：优先 Go 实现 wsd 解析，PHP 只做上传接收，文件落盘，交给 Go 服务处理，这是最优路线。

> 
> 不建议直接把 wsd 二进制解析耦合进 PHP 网页业务代码。
